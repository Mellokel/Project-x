# Правила разработки сайта поездки

## Направление

- Сохранять существующий спокойный стиль: мягкий чёрный, хвойный зелёный, тёмный коричневый, приглушённое золото. Не менять палитру и композицию без запроса пользователя.
- Сайт работает через один index.html с экранами и hash-маршрутами. Сохранять прямые ссылки, историю браузера, состояние элементов при переходах и совместимость с GitHub Pages в подкаталоге /Project-x/.
- При работе с оформлением применять установленный frontend-design; при проверке интерфейса — web-design-guidelines. Общие рекомендации навыков адаптировать к этому проекту и его существующему дизайну.

## Исходники и сборка

- Главная: site-source/home.html. Дорога: site-source/road.html.
- Участники и расселение: participants.json. Шаблоны профилей: scripts/build-participants.py.
- index.html и старые HTML-адреса генерируются командой python3 scripts/build-site.py. Не вносить содержательные правки только в генерируемые файлы.
- После изменения шаблонов или данных выполнить сборку и python3 scripts/check-site.py; для изменённого JavaScript — node --check.
- Не публиковать автоматически во внешние сервисы. Обновление локальных файлов не означает обновления GitHub Pages.

## Мобильная адаптация — обязательная часть UI-изменений

- Сначала учитывать узкий экран. Проверять затронутые экраны на ширинах 360, 390 и 430 px, планшете 768 px и десктопе 1280 px. Для изменения одной детали достаточно проверки соответствующего экрана; общая навигация требует проверки поездки, дороги, участников и одного профиля.
- Проверять не только CSS, но и реальный браузерный вид: отсутствие горизонтального переполнения всей страницы, наложений, обрезанных имён, цен и кнопок. Горизонтальная прокрутка допустима внутри явно выделенного меню или временной шкалы.
- У интерактивных элементов стремиться к области нажатия не меньше 44 × 44 CSS px. Не полагаться на hover: любое действие должно работать касанием и с клавиатуры.
- Основной текст должен оставаться читаемым на телефоне; не уменьшать его ради размещения в одну строку. Длинные имена и подписи должны переноситься.
- Сверху закреплена строка разделов текущей страницы; основные страницы находятся в плавающем таббаре снизу. Учитывать безопасные области и отступ под таббаром. Подсвеченный раздел и фокус должны быть видны; переходы по якорям не должны прятать заголовки под шапкой.
- Проверять обе ориентации для затронутой закреплённой навигации и крупных обложек, увеличение текста до 200%, видимый фокус и prefers-reduced-motion.
- Использовать адаптивные сетки и изображения без искажения пропорций. Не загружать оригиналы многомегабайтных фото вместо оптимизированных копий и не добавлять внешние блокирующие шрифты.
- Сохранять ограничение загрузки неактивных экранов: фотографии из HTML-шаблонов не должны загружаться все сразу.
- В отчёте указывать, какие размеры реально проверены; не выдавать наличие media queries за выполненную браузерную проверку и эмуляцию за проверку на физическом телефоне.
